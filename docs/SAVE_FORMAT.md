# 第三版存档兼容与检查点

永久档仍为 `user://profile_v2.json`，结构 version=3。settings.cfg 保存 master/volume/shake/numbers/effects 以及 bindings 分组。应用 config/name 保持“ 三途试炼 · First Playable ”原值，避免因换名生成新用户目录；第三版窗口标题由脚本设置。

外层 `{payload: 序列化 JSON 字符串, checksum: payload 的 SHA-256}`。先写 `.tmp`，flush/close，再备份有效旧主档为 `.bak`，替换主档。读取失败尝试备份；两者都无效时只读临时开档，保留原文件。来自更高结构版本的存档禁止写回。校验用于损坏检测，不是防篡改。

## V2 → V3

保留装备 UID、词条、强化等级、角色等级/技能等级、天赋已花点数、穿戴、货币、成就和收集记录。新增 favorites、abyss_best[3]、checkpoint、v3_grant。首次缺少 v3_grant 时补 3 材料，标志随同保存，不重复补发。已完成第四章的档案解锁第五章。

章节整数 ID 与技能等级在 JSON 加载后规范为整数，修复 Array.has 的数字类型差异。旧档不重新随机生成装备。新技能上限 10，旧的 1–3 级仍合法。

## 深渊检查点

仅五层整备点显式“保存深渊并退出”生成。检查点保存 version、唯一 run id、已完成与下一层、职业、生命、随机种子、字符串形式的 64 位 RNG state、Buff 分量/层数、临时技能、不屈已用状态、已出售商店库存、用时/击破/收益统计、道具冷却及护盾状态。

进阶状态由 Buff 层数确定，永久技能由同文件角色记录确定，无需重复两份可能冲突的数据。五层整备没有存活敌人，下一层重置主动技能，所以无需保存战场实体或主动技能剩余冷却。

检查点与已入账永久收益写进同一个校验文件。继续时先清空检查点并成功写盘，再恢复整备状态；失败会恢复内存检查点、阻止继续并提示。库存 sold 状态、奖励已领取标志、下一层顺序和 RNG 同时恢复，不能正常重开刷同层或刷新商店。玩家可以在恢复后的安全整备点再次保存退出，但不会重新获得楼层奖励。

普通战斗中退出不建立检查点。金币/经验等已保存永久收益保留，本局构筑失去。自动保存周期约 3 秒；突发断电仍可能丢失最近尚未保存的收益。临时文件+备份不保证所有文件系统上严格原子替换，测试没有模拟突然断电。

工程内测试档仅为 tests/profile-v3-fixture.json 与 tests/checkpoint-integration-v3.json 等隔离路径，打包排除它们。真实 profile_v2.json 未被自动测试读取或覆盖。请勿同时开两个实例操作同一真实存档。
